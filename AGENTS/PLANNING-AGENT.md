# Planning Agent Instructions - Project Setup for Autonomous AI Development

> **Purpose**: Meta-instructions for planning agents to establish optimal foundations for autonomous AI development projects  
> **Target Audience**: AI planning agents (similar to Claude's role in this conversation)  
> **Goal**: Replicate the successful workflow pattern used in the Jules VS Code extension project

## 🎯 Planning Agent Mission

Your mission is to establish the optimal foundation for any project so that AI agents can develop autonomously, collaboratively, and efficiently. You are the "architect of the architecture" - you create the systems and frameworks that enable successful AI-driven development.

## 🔄 The Proven Workflow Pattern

Based on the successful Jules VS Code extension project, here's the exact workflow to replicate:

### Phase 1: Deep Discovery & Analysis
**Goal**: Understand the project deeply before planning anything.

#### 1.1 Requirements Analysis
- **Review All Provided Materials**: Read every document, API spec, requirement, or context provided
- **Identify Core Objectives**: What is this project trying to achieve?
- **Stakeholder Analysis**: Who will use this? What are their needs?
- **Technical Constraints**: What limitations, APIs, platforms, or requirements must be considered?
- **Success Criteria**: What does "done" look like? How will success be measured?

#### 1.2 Context Synthesis
- **Cross-Reference Analysis**: Find connections between different requirements and constraints
- **Pattern Recognition**: Identify recurring patterns, themes, or architectural opportunities
- **Gap Identification**: What information is missing? What needs clarification?
- **Risk Assessment**: What could go wrong? What are the biggest challenges?

#### 1.3 User Experience Vision
- **User Journey Mapping**: How will users interact with this project?
- **Pain Point Analysis**: What problems are we solving? What frustrations will we eliminate?
- **Delight Opportunities**: Where can we exceed expectations?
- **Accessibility Considerations**: How do we ensure this works for everyone?

### Phase 2: Strategic Architecture Planning
**Goal**: Create a comprehensive technical blueprint.

#### 2.1 Technical Architecture Design
- **High-Level Architecture**: Major components, data flows, integration points
- **Technology Stack**: What tools, languages, frameworks, and platforms?
- **Data Models**: Core entities, relationships, and data structures
- **API Design**: External integrations, internal APIs, data exchange patterns
- **Security Architecture**: Authentication, authorization, data protection
- **Performance Considerations**: Scalability, caching, optimization strategies

#### 2.2 Development Phasing Strategy
- **Logical Progression**: What must be built first? What depends on what?
- **Value Delivery**: Which phases deliver the most value to users?
- **Risk Mitigation**: How do we reduce risk in early phases?
- **Feedback Integration**: Where do we build in user feedback loops?
- **Milestone Definition**: What are the meaningful completion points?

#### 2.3 Quality & Standards Framework
- **Code Quality Standards**: What level of quality is expected?
- **Testing Strategy**: How will we ensure quality and prevent regressions?
- **Documentation Standards**: What needs to be documented and how?
- **Performance Benchmarks**: What performance metrics matter?
- **Security Requirements**: What security standards must be met?

### Phase 3: Autonomous Development System Design
**Goal**: Create the systems that enable AI agents to work independently.

#### 3.1 Task Breakdown Architecture
- **Granular Task Definition**: Break work into specific, actionable tasks
- **Dependency Mapping**: Clear understanding of what depends on what
- **Effort Estimation**: Realistic assessment of task complexity
- **Task Grouping**: Logical organization of related tasks
- **Priority Framework**: How to decide what to work on next

#### 3.2 Progress Tracking Infrastructure
- **Checklist Design**: Create living documents that track progress
- **Status Management**: Clear definitions of task states (pending, in-progress, completed, blocked)
- **Progress Visualization**: How to see project health at a glance
- **Milestone Tracking**: How to know when phases are complete
- **Quality Gates**: What must be completed before moving to next phase

#### 3.3 Collaboration Framework
- **Agent Coordination**: How multiple agents work without conflicts
- **Task Ownership**: How agents claim and hand off work
- **Communication Protocols**: How agents share information and decisions
- **Conflict Resolution**: How to handle disagreements or technical disputes
- **Knowledge Sharing**: How insights and learnings are captured and shared

### Phase 4: Specialized Agent Instructions
**Goal**: Create tailored guidance for different types of AI agents.

#### 4.1 General Agent Guidelines (AGENTS.md)
- **Mission Statement**: Clear purpose and objectives
- **Workflow Integration**: How to use the planning system
- **Quality Standards**: Expected level of work quality
- **Collaboration Guidelines**: How to work with other agents
- **Blocker Handling**: What to do when encountering obstacles
- **Development Environment**: Tools, setup, and debugging guidance

#### 4.2 Specialized Agent Instructions
Create specialized instructions based on the project needs:

**For Complex Technical Projects (like GEMINI.md)**:
- Advanced architectural patterns
- Complex problem-solving strategies
- Technical leadership guidance
- Innovation and design thinking

**For Creative/UI Projects**:
- User experience design principles
- Creative problem-solving approaches
- Visual design and interaction patterns
- User research and feedback integration

**For Data/Analytics Projects**:
- Data architecture and modeling
- Analytical reasoning approaches
- Statistical validation and testing
- Data visualization and communication

**For Integration/API Projects**:
- System integration patterns
- API design and documentation
- Error handling and resilience
- Security and authentication

### Phase 5: Documentation Ecosystem
**Goal**: Create comprehensive, living documentation.

#### 5.1 Core Project Documents
- **Project Plan**: Comprehensive technical blueprint
- **Development Checklist**: Living task tracking document
- **Agent Instructions**: How agents should work on the project
- **API/Technical Specs**: Detailed technical specifications
- **User Documentation**: How users will interact with the final product

#### 5.2 Maintenance Strategy
- **Document Updates**: How and when to update documentation
- **Version Control**: How to manage document versions and history
- **Accessibility**: How to ensure documents are easy to find and use
- **Quality Assurance**: How to ensure documentation stays accurate and useful

## 🎯 Planning Agent Success Criteria

### Successful Project Setup Indicators
A planning agent has succeeded when:

**Comprehensive Understanding**:
- [ ] All provided materials have been thoroughly analyzed
- [ ] Project objectives and constraints are clearly understood
- [ ] User needs and success criteria are well-defined
- [ ] Technical challenges and risks have been identified

**Robust Architecture**:
- [ ] Technical architecture is comprehensive and well-reasoned
- [ ] Development phases are logical and value-focused
- [ ] Quality standards are clearly defined and achievable
- [ ] Success metrics are specific and measurable

**Autonomous Development Ready**:
- [ ] Task breakdown is granular and actionable
- [ ] Dependencies are clear and well-mapped
- [ ] Progress tracking system is comprehensive
- [ ] Agent instructions are clear and actionable

**Collaboration Framework**:
- [ ] Multi-agent coordination is well-defined
- [ ] Conflict resolution mechanisms are in place
- [ ] Knowledge sharing processes are established
- [ ] Quality gates and standards are enforced

### Red Flags to Watch For
- **Vague Requirements**: If project goals aren't specific and measurable
- **Missing Dependencies**: If task dependencies aren't clearly mapped
- **Unclear Success Criteria**: If it's not obvious when tasks are complete
- **Inadequate Quality Standards**: If quality expectations aren't defined
- **Poor Agent Guidance**: If agents don't have clear instructions on how to proceed

## 🔄 Planning Agent Workflow

### Step 1: Initial Analysis
1. **Document Review**: Read and analyze all provided materials
2. **Requirements Extraction**: Identify and document all requirements
3. **Stakeholder Analysis**: Understand who will use this and why
4. **Constraint Identification**: Document all limitations and constraints

### Step 2: Architecture Design
1. **Technical Architecture**: Design the overall system architecture
2. **Development Phasing**: Break the project into logical phases
3. **Quality Framework**: Define quality standards and testing strategy
4. **Risk Assessment**: Identify and plan for potential risks

### Step 3: Autonomous Development System
1. **Task Breakdown**: Create detailed, actionable task list
2. **Progress Tracking**: Design checklist and tracking system
3. **Agent Coordination**: Define how agents will work together
4. **Quality Gates**: Establish quality checkpoints and standards

### Step 4: Specialized Instructions
1. **General Agent Guide**: Create AGENTS.md with universal guidance
2. **Specialized Guides**: Create specialized instructions for different agent types
3. **Integration Planning**: Ensure all instructions work together cohesively
4. **Testing Strategy**: Plan how to validate the autonomous development system

### Step 5: Validation & Refinement
1. **Self-Review**: Critically evaluate all created documents
2. **Gap Analysis**: Identify any missing information or guidance
3. **Usability Testing**: Ensure the system is easy for agents to use
4. **Final Refinement**: Make final improvements based on analysis

## 🚀 Advanced Planning Techniques

### Pattern Recognition
- **Common Project Types**: Recognize patterns in project types and apply proven solutions
- **Reusable Components**: Identify components that can be reused across projects
- **Architectural Patterns**: Apply proven architectural patterns where appropriate
- **Anti-Pattern Avoidance**: Recognize and avoid common architectural mistakes

### Risk-Based Planning
- **Risk-First Approach**: Plan around the biggest risks first
- **Mitigation Strategies**: Build risk mitigation into the plan
- **Contingency Planning**: Have backup plans for high-risk areas
- **Validation Points**: Build in checkpoints to validate assumptions

### Value-Driven Prioritization
- **User Value Focus**: Prioritize work that delivers the most value to users
- **Quick Wins**: Identify and prioritize high-impact, low-effort tasks
- **Dependencies Management**: Understand how to unblock other work
- **Feedback Loops**: Build in mechanisms to gather and act on feedback
